# c-0026 - The manual existed

## Selection

User redirect onto **n-0011**, the only surviving route, from five observations
against the running plugin: context-menu parity, a visual overhaul carrying the
real hierarchy, a per-session task panel, resource metering, and an editor
hand-off.

## The finding that reframed the cycle

`cmux docs sidebars` and `cmux docs api` publish a **custom sidebar authoring
contract** and a **CLI contract**. Neither had been read in the 27 hours this
plugin has existed. Both were fetched this cycle.

The authoring guide says:

> "unsupported syntax is skipped ... never crashes"

That is the documented mechanism behind **every** silent render failure recorded
in `maestro.swift`. `cmux sidebar validate` reporting OK on a sidebar that
renders nothing is correct, specified behaviour. Four separate debugging rounds -
absent-not-null optionals, arithmetic in modifier arguments, the unusable `\n`
escape, zero-width frames that do not hide - were reading-the-manual work
rediscovered by bisection.

This is the fifth occurrence of this session's recurring meta-defect, and the
first where the missing check was not a measurement but a **document**.

## What the contracts settled without asking

| Ask | Was assumed | Actually |
| --- | --- | --- |
| Context-menu parity | Build | `workspace-action` covers pin, rename, set-description, move-up/down/top, close-others/above/below, mark-read/unread, **set-color**; `tab-action` adds duplicate, new-terminal-right, close-left/right |
| CPU and RAM | Unknown feasibility | `cmux top` already reports per window, workspace, pane, **and surface** |
| Editor hand-off | Build | `cmux open <path-or-url>` runs through the same dispatcher sidebar actions use |

And one guess was retired outright: cmux injects the **protected** variables
`CMUX_SURFACE_ID`, `CMUX_TAB_ID`, and `CMUX_WORKSPACE_ID` into every terminal it
spawns. A Copilot Session therefore knows exactly which terminal it occupies,
which makes the **workspace -> terminal -> session -> subagent** hierarchy
directly representable and replaces the `cwd`-plus-newest-mtime heuristic that
c-0025 recorded as a defect.

## Decisions

**1. Publishing is an ephemeral, hook-spawned, self-terminating watcher.**
The loop first recommended a `launchd` agent. The user rejected a resident
process - *"that feels like a fragile and difficult task"* - and asked how
Conductor does it. Conductor uses **no daemon**: each hook arms a lock-guarded
background child that samples while events keep arriving and exits once they go
quiet. Strictly better against the stated objection, and the loop should have
found it before proposing the daemon.

*Accepted risk, recorded rather than smoothed over:* the user chose Conductor
parity including its `trap '' HUP`, which makes the child survive a hangup.
**c-0006 - this project's founding forensic finding - was a detached
`herdr server` outliving its parent by two days.** Trigger: the first observed
watcher surviving cmux exit.

**2. The task list is Copilot's own session `todos`, read-only.** cmux's native
`cmux todo` was a real candidate - states, `user|agent` origin, its own pane -
and was **dropped on decisive evidence**: it is not bindable in a custom sidebar
at all, so rendering it would mean mirroring cmux state into Maestro's channel
where it can go stale. Maestro never mutates Copilot's task store.

**3. The panel is shown only when the highlighted terminal has a task list.**

## Two platform blocks

Both were requested and neither is available:

- **Vertical resizing.** `VSplitView` is absent from the authoring contract and
  from the application binary; only `HSplitView`'s horizontal, persisted divider
  exists. Unsupported syntax is silently skipped, so it would simply vanish.
- **Expand-to-drill-into completed tasks**, and tabs, and a Clear button, all
  need `@State`, which the contract documents as unsupported.

*Candidate resolution, unmeasured:* `cmux sidebar open <name>` opens a sidebar as
a **Bonsplit pane**, and panes are resized and persisted by cmux itself, so
resizability may come from the pane system rather than the sidebar language.
