## Evidence

### A confirmed requirement was falsified

`requirements.md` has recorded since c-0015 that *"Tauri reaches Playwright
through WebDriver."* **Wrong on macOS.** `WKWebView` exposes no Chrome DevTools
Protocol, so Playwright is out entirely, and Tauri's own documentation states
that driving `tauri-driver` directly supports "only Windows and Linux ... as
macOS has no WKWebView driver tool available".

The working path is **WebdriverIO with `@wdio/tauri-service`**, which embeds a
W3C WebDriver server *inside the application binary*. That is a materially
different cost from Electron's: **the route must modify the product under test
to make it testable.** CrabNebula's macOS driver is commercial; Appium's `mac2`
driver reaches the accessibility layer but not the webview DOM.

### Two uncounted facts, pulling in opposite directions

**Swift has the strongest verification story of the four.** `XCUIApplication`
drives an already-packaged `.app` by bundle identifier or file URL, with no test
target compiled into the product - the opposite of Tauri's requirement.

**And no Swift SDK exists.** GitHub publishes official Copilot SDK bindings for
TypeScript, Python, Go, **Rust**, Java, and .NET. So n-0005 gains a native seam
with no Node sidecar, and n-0006 must spawn a sidecar or hand-roll JSON-RPC
against no published specification.

**SDK language-binding availability is therefore a second rubric axis**, and
together with the Tauri finding it partly inverts the ranking c-0015's criterion
implied: Swift was assumed middling and is strongest on automation; Tauri was
assumed Electron-like and is materially worse.
