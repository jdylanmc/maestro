### Gap 2 - slice step 5 (Attention): NOT met, and the reason is new

Measured `0 requested / 0 completed / 0 pending`. The event log contains **no
permission events of any kind** - `tool.execution_start` goes straight to
`tool.execution_complete`, the same shape c-0013 measured for ACP.

**The cause is neither a runtime limitation nor a route limitation.** Reading
`~/.copilot/permissions-config.json` shows a standing **approve-for-location**
rule on `/Users/dylan/git`, granting `write: *`, `mcp: *`, and a command list.
The Fleet worktree lives under that path, so `git status` was **pre-approved and
correctly never requested**. Separately, `git status` is read-only and is treated
as safe regardless.

This is the **third distinct reason** acceptance-slice step 5 has failed to fire
across the project - after ACP surfacing no permission events (c-0013) and the
SDK `onPreToolUse` hook not changing behaviour (c-0020) - and it is the first one
that is **the system working as designed rather than a gap**. Recorded as such:
the requirement is sound, the evidence environment was wrong.

**Consequence for the Acceptance Harness:** a step-5 assertion is only valid
against a Fleet whose working directory is **not** covered by a standing
approval, or against a command outside the approved set. Otherwise the harness
measures the operator's local trust configuration rather than the route. Nothing
in the harness design accounted for this, and it would have produced a confident
false negative on any machine with a broad approval rule.

### Gap 3 - teardown on cmux: PARTIALLY closed

**Process ownership, measured for the first time on this route.** Fleet alpha's
live Session occupied **one process group (pgid 15284) holding 8 processes**: an
`agency` wrapper, `copilot` 1.0.81-3, three Model Context Protocol servers
(devbox, playwright, computer-use), and two `node` children. Every one resolved
to the Fleet's own worktree by `lsof` cwd. This reproduces c-0012's Electron
shape exactly - 8 processes, MCP servers included, one group - and confirms that
a cmux pane gives a Fleet a **clean per-Fleet process-group boundary for free**.

The observing session was pgid 26472, a different group, so the boundary is real
rather than an artifact of everything sharing one group.

**Graceful path: 0 survivors of 8.** The operator quit Copilot and cmux exited;
all 8 processes were gone, including all three MCP servers, and no process
remained with a cwd inside the sandbox.

**What this does and does not establish.** It measures the *friendly* path - the
agent shut itself down before the host went away. It does **not** measure the
case `N0.1` exists for, which the user stated as *"I close the UX and everything
stays running"*: host disappears while the agent is **still live**. That is
exactly where c-0012 measured `SIGTERM` stalling at 5 survivors on Electron, and
it remains **unmeasured on cmux**. Recorded as a partial closure rather than a
pass, because reporting 0 survivors without naming the scenario would overstate
it in the direction the project has already been burned by twice (c-0009's
synthetic trees, c-0016's fuse claim).
