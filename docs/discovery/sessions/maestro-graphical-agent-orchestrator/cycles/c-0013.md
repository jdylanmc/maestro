# Cycle c-0013 - ACP is the seam, and it does not ask permission

## The first cycle priority debt ever chose

c-0012 left six debt rows. Rule 2 fired for the first time in the session's
history and selected `n-0008` - the integration mode - over everything else. The
user had independently pre-approved a prototype for exactly that node, which
agreed with the deterministic selection rather than overriding it.

## What the probe found

A minimal JSON-RPC-over-stdio client against `copilot --acp`.

**ACP works, and it is richer than the event log.** `initialize` ->
`session/new` -> `session/prompt` completed cleanly. Streaming arrives as
`session/update` notifications: `agent_message_chunk` for text, and `tool_call`
/ `tool_call_update` carrying `title`, `kind`, `status`, `rawInput`, and
`rawOutput`. That is the per-node Activity line the interface requirements ask
for, as structured data rather than scraped terminal output.

**`session/load` resumes a session with its history.** Asked what command it had
been given earlier, the resumed session answered "You asked me to run `touch
blocked.txt`." Restart reconciliation now has a demonstrated mechanism, which no
previous cycle had.

**`session/list` returns 50 sessions** with `sessionId`, `cwd`, `title`, and
`updatedAt` - a ready-made Fleet reconciliation surface.

Then the two holes.

**ACP never asks permission.** No `session/request_permission` arrived, and the
session's `events.jsonl` recorded **zero** permission events. The shell command
simply ran. Confirmed twice, with and without declared client capabilities, and
controlled against c-0012's pseudo-terminal session in the same environment,
same working directory, same binary - which did prompt.

**ACP will not name a session.** `session/new` accepted a `name` parameter and
ignored it; `workspace.yaml` shows `user_named:` empty.

## The decision, and a recommendation that deserved to lose

The loop recommended that Maestro own the permission boundary: deny sensitive
tools at the process level, expose gated equivalents through a Maestro-controlled
Model Context Protocol server, and raise Attention from its own pending
approvals.

The user delegated the decision and supplied one sentence that ended it: *"I
usually run in yolo mode with many permissions."*

That layer would have been built to satisfy a slice step rather than a user. It
was dropped. What replaced it:

- **ACP is adopted** as the integration seam.
- **Attention is derived from what the seam provides** - `session.error`,
  `abort`, and the tool-call status stream - with unmatched
  `permission.requested` retained wherever a mode surfaces it.
- **ACP permission support is an upstream dependency**, not a Maestro gap. The
  protocol defines `session/request_permission`; this build does not send it.
  Re-test trigger: every Copilot CLI upgrade.
- **A Fleet is bound by `sessionId`**, with Maestro owning the display name.

## Two confirmed requirements changed under delegation

Both are flagged revisitable, because the user delegated rather than confirmed:

1. **Acceptance-slice step 5** now reads "Fleet A enters a state that requires
   the human - a pending permission where the mode surfaces one, otherwise an
   error or abort - and Attention surfaces on that Fleet and no other." The
   confirmed intent, per-Fleet Attention, is preserved; the mechanism is no
   longer pinned to a signal ACP does not emit.
2. **The runtime-naming requirement** narrows from "Maestro names the runtime's
   Session" to binding by `sessionId` with a Maestro-owned display name. The
   goal it served - a Fleet stays identifiable outside Maestro - survives through
   `session/list` titles and `workspace.yaml`.

## Limitations

- No subagent was spawned, so `subagent.started` was never exercised through
  ACP; the tree's live path is confirmed only for the shared `events.jsonl`.
- The permission finding is a negative result on one build, whose ACP server
  reported a different version (1.0.81-5) than the invoking binary (1.0.80).
- Nothing was measured about what a client should render while a tool call is
  `pending`.
