# Cycle c-0010 - Isolation becomes total, and two research claims fail

## What this cycle settled

Four bounded read-only subagents researched the four independent open research
questions in parallel. Their reports were treated as untrusted evidence. The two
claims that would have changed the architecture were re-measured in the parent
loop, and **both were wrong**.

Then the user closed the isolation question on both axes.

## The falsifications

**The subagent tree is not built on `parentId`.** The research reported it as the
parent link, with nesting up to depth 16. Measured against a 41,928-event
session: `parentId` held 41,927 distinct values, every one resolving to an event
id and none to an `agentId`. It is a linear event-chain pointer, so two
subagents launched consecutively in the same parallel batch appear as parent and
child. Rebuilding on the sound edge - `subagent.started.data.toolCallId` joined
to the `agentId` of the spawning agent's `tool.*` event - gives a real maximum
depth of **2**: 51 root-spawned, 72 at depth 1, 9 at depth 2, with 72 of 132
spawned by one agent.

The consequence for the product is that the tree view must be built for
**breadth, not depth**, and that a tree built the obvious way would have
rendered cleanly and been fiction.

**The messaging table is used, and it is not a peer channel.** The research found
`inbox_entries` empty and called it inert. Across all 674 local session
databases it holds 27 rows, so the sample was too small. But every sender is a
`background-agent` or `sidekick-agent` reporting to its owning session, never a
peer. It is the intra-Fleet subagent channel. There is no inter-Fleet channel to
inherit.

## The decisions

**Sibling awareness: none.** Since the runtime provides no peer channel, any
cross-Fleet awareness would have to be invented. The user declined it for the
MVP. The human is the only integration point between Fleets. This **reverses**
the c-0007 requirement that "a Fleet must know it is not alone," which is
recorded as a reversal rather than quietly refined.

**Fleets are isolated to worktrees.** The user's words. Worktree-per-Fleet moves
from strong default to hard rule; Fleets never share a checkout. `CONTEXT.md`
and both lexicons were corrected.

Together these make isolation total on both axes - no shared checkout, no shared
channel. A Fleet becomes a unit that can be reasoned about alone, and cross-Fleet
conflict resolution stops being a problem the MVP has to solve.

**`herdr` is prior art, not a dependency.** The user's ruling: a v1.0 sample, not
written off, very similar to what is being built. It stays a reference point and
does not enter the glossary.

## What this costs

Mandatory worktrees promote the `worktree-cost` finding from curiosity to the
load-bearing constraint. Git itself is cheap - ~2.6 MiB and ~50 ms per worktree,
object store shared. What scales badly is duplicated untracked and build state
per worktree, which is exactly what a large monorepo has most of. Sparse
checkout is the strongest available mitigation.

## Attention, finally defined

`AT_RISK` is not computable from generic events. Attention reduces to an
**unmatched `permission.requested`**, plus `session.error` and `abort` as
terminal states. `assistant.turn_end` means the assistant yielded, not that a
human is needed, and must not be treated as Attention.

This is sound in shape but **unproven in the blocking case**: no unresolved
permission request exists anywhere in local evidence, so the predicate has never
been observed firing.

## Honest limitations

Depth and breadth come from one machine's history and describe how this operator
works, not a bound on what Copilot can produce. Worktree cost was measured on a
small repository, not the target monorepo. The Attention predicate is untested
against a real block.
