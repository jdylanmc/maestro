# Cycle c-0011 - The tree was one node, and "done" was undefined

## The finding that framed the cycle

After ten completed cycles this session's tree still contained **exactly one
node**. Packaging lifecycle, live Copilot signal handling, the Attention
predicate, the worktree ceiling, and three entirely unexplored implementation
routes were all held inside `n-0000`'s prose.

That is not a tidiness problem. It had three concrete effects:

- nothing below map tier could be promoted, because nothing below map tier
  existed;
- no question carried its own priority, maturity, or dependency, so "what is
  left" had to be re-derived from prose every single cycle;
- the fog scan returned one row, which made the deterministic selection rules
  inert - rule 6 was the only rule that could ever fire.

Each cycle individually looked productive, and the checkpoints are accurate.
Only the cumulative shape shows the failure.

## The anchor had drifted backwards

Issue #1's timestamp had moved past the recorded `anchor-revision`, which
normally means the anchor moved underneath settled understanding. Reading it
showed the reverse. Its "Isolation" section still records worktree-per-Fleet as
"reinforced but not enforced" and still requires that "A Fleet must know that
other Fleets may be working concurrently." **Both were reversed in c-0010.**

Durable state is *ahead* of the anchor, so nothing is invalidated. But the anchor
is the first thing every cycle reads, and one that contradicts confirmed state
will eventually be read as authority by a cycle that has forgotten why it is
stale. Recorded as a tracker divergence needing `/discovery`; this loop may not
run a tracker command itself.

The same rot was found in the root map, which still described Fleets as
"preferring one Worktree each". Corrected in this cycle.

## The decisions

**All four routes go to a complete MVP.** The loop recommended driving Electron
alone to completion and reducing v1.1, v3, and v4 to bounded feasibility probes,
arguing that the MVP contract exists to select an implementation rather than to
ship four. **The user overruled it.** That is recorded as an overruled
recommendation, not as a decision the loop reached: the loop's argument was not
refuted, it was outranked, and the cost it named - roughly four times the work,
three of them discarded - is real and unmitigated. What it buys is a genuine
side-by-side and a defensible final selection, which is the user's call to make.

**Order is by evidence, not by version:** v2 Electron, then v1.1 WezTerm, then
v3 Tauri/Rust, then v4 native macOS Swift. Electron leads because it is the only
route carrying measured evidence - c-0009's zero-survivor teardown across three
process groups. Starting anywhere else would strand that evidence and reopen
process ownership, the hardest requirement, on a route that has never proven it.

**"Complete" is now executable.** The acceptance slice had been unresolved since
c-0001, where it was a list of capabilities in superseded vocabulary that could
never say whether a route had finished. It is now one scripted six-step flow,
identical across every route: two named Fleets in enforced Worktrees, each with
its 1:1 primary agent window; a live subagent tree with correct parentage;
Fleet-scoped re-selection; Attention surfacing on a permission request; and a
quit-and-relaunch that auto-Parks, leaves zero survivors, and returns both Fleets
with identity, history, Worktree, and resumed Session. Every step restates a
requirement already confirmed between c-0005 and c-0010, so the slice adds no
scope - it makes the existing contract testable.

**Two things the loop did not propose, and the user added.** A per-stack
executive report is a first-class deliverable rather than a by-product. And a
stack that cannot build the app is **rejected** - a legitimate terminal verdict,
not a failure. A rejected route still produces its report, and the reason it
failed is an input to the comparative evaluation rather than an absence from it.

## The sequencing defends itself

"One at a time" is encoded as the `depends-on` chain, not written down as a note,
and that has a mechanical consequence. `n-0003` enters at maturity `researched`,
which sits exactly at the priority-maturity invariant's floor, so the P1 nodes
depending on it generate **no** debt and the table stays empty. The moment
`n-0003` is weakened below that floor, `n-0004` and `n-0007` become debt rows and
the loop is *required* to stop deepening them until Electron recovers.

The user's sequencing decision is therefore enforced by the invariant rather than
by anyone remembering it.

## The known unknown

The 8-Fleet ceiling under mandatory worktrees was **accepted as unknown**, not
answered. c-0010 had already reduced it to duplicated untracked and build state -
git's own cost is ~2.6 MiB and ~50 ms per worktree with a shared object store,
and file descriptors are nowhere near binding. What remains needs a real
repository, and the user does not have a target in mind.

- **Risk:** admission control and the in-panel resource meter are being specified
  against a ceiling never measured against a repository large enough to bind it.
  A wrong calibration surfaces only under load, on a user's real repository.
- **Trigger to revisit:** the first real Fleet count above 3 on a repository with
  heavy dependency or build state, or the adoption of sparse checkout, which
  c-0010 identified as the strongest mitigation.

## Vocabulary, deliberately not escalated

`Acceptance Slice` was added to the session lexicon as `candidate` and **not**
handed to `/domain-mapping`. It is a discovery-process artifact - the shape of
this session's definition of done - not a Maestro domain entity. It never appears
in the product, has no lifecycle, and has no runtime meaning to collide with.
`CONTEXT.md` should not carry it.

Separately: the user reached for "tabs/sessions/workspaces/whatever" a fourth
time. That is recorded as evidence that the confirmed term has not displaced the
loose ones in speech - a documentation signal - and explicitly **not** as lexicon
drift. The trailing "whatever" shows the concept was being gestured at, not
named, and `Fleet` has an Architecture Decision Record behind it.

## Honest limitations

- **No measurement was taken this cycle.** Everything here is structural or
  decisional. The one measurable question was explicitly deferred as unknown.
- **The slice's "adds no scope" claim is unverified.** Every step was mapped to a
  confirmed requirement by reading, not by tooling, and nothing independently
  checked that mapping.
- **Two of the six steps have never been observed working anywhere.** Step 5
  depends on the Attention predicate, which has never been seen firing because no
  unresolved `permission.requested` exists in any local evidence. Step 6's
  restart path is proven only for teardown (c-0009), never for reconciliation on
  relaunch.
- **Promotion was not attempted.** The gate needs fog `cleared` and maturity
  `promotion-ready`; nothing is close. The four route nodes already have standing
  tracker items (#27, #4, #23, #24) and will bind to those rather than create
  duplicates.
- **The role split is now standing policy** and will shape later cycles: the user
  owns product intent, scope, and sequencing; the loop owns tree structure,
  decomposition, and technical judgement. Purely structural questions no longer
  spend group budget. This was granted in one line and has not been revisited.
