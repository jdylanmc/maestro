# c-0027 - The vocabulary already existed on both sides

## Selection

User redirect onto n-0013: make each terminal's agent state visible, and use
the Maestro icon.

## One ask closed by the contract, with no question asked

The c-0026 corollary - check the published contract before treating platform
behaviour as unknown - was applied first, and it closed the icon outright.

- The sidebar renders **only SF Symbols**. `Image(systemName:)` and
  `Label(_, systemImage:)` are the whole surface; `AsyncImage` and `.resizable`
  are on the documented unsupported list, and no file-loading image view exists.
- cmux's application icon setting `app.appIcon` accepts exactly `automatic`,
  `dark`, and `light`, enumerated from the binary. There is no custom path.

So `Maestro.icns` has **no home on this route**. Recorded as **n-0015**, fog
`cleared`, so no later cycle re-proposes it. The ask is not deferred; it is
unavailable, and the reason is written down.

## The state ask was half-built already, on both sides

Every signal exists in the Copilot session event log, enumerated from a live
1 MB log this cycle: `session.start`, `assistant.turn_start`,
`assistant.turn_end`, `agent_idle`, `tool.execution_start`,
`tool.execution_complete`, `permission.requested`, `permission.completed`,
`subagent.started`, `subagent.completed`, `session.warning`,
`factory_limit_reached`, `factory_completed`.

**Waiting-for-human is the one state already proven.** An unmatched
`permission.requested` joined by `requestId` is the Attention predicate this
session first observed firing in c-0012 and confirmed on cmux in c-0024.

And cmux ships the vocabulary: `cmux workspace status` carries `todo`,
`working`, `needs-attention`, `review`, `done`, with an inferred value and a
manual override.

Two mismatches made it a real decision rather than a free win: the lane is
**per workspace** while agents are **per terminal**, and the lane is **not in
the sidebar binding set**, so Maestro cannot read back what it writes.

## Decisions

**1. Push the native lane, against the loop's recommendation.** The loop
recommended own-badges-only on the grounds that a per-workspace lane cannot
represent per-terminal agents without lying. The user chose to push it so the
signal survives with Maestro's sidebar closed.

**The objection was answered rather than overruled.** Aggregating
**most-urgent-wins** - `needs-attention` > `working` > `done` - makes the lane
true at workspace granularity: if any agent is blocked on the operator, the
workspace is blocked on the operator. Last-writer-wins was rejected outright.
Subagents never push; only the terminal-level agent does.

**2. A manual pin is overridden only for `needs-attention`.** Maestro stays out
of a lane the operator set by hand except in the one case worth interrupting.

**3. Finished means `agent_idle`.**

**4. Collapse is driven by selection, plus auto-expand on `needs-attention`.**
*User: "in the collapsed state of a workspace I want to just visually see the
state of that workspace, but not all its subagents."* With no `@State` there is
no disclosure control, so selection - already persisted by cmux - is the only
available trigger, and it is also what cmux's own performance guidance
recommends. A collapsed workspace shows its state badge plus running, failed,
and done counts.
