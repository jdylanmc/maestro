# c-0028 - The platform had already built it

## Selection

User-directed documentation sweep: read the remaining cmux docs and determine
which open questions they answer. `cmux docs` lists seven topics; c-0026 read
two. This cycle read `dock`, `agent-hooks`, `feed`, `notifications`, the cmux
skill, and the machine's own `~/.cmuxterm/events.jsonl` event stream.

It answered more than it was asked to.

## F1 - Three per-tab channels existed the whole time

`cmux` documents `set-status`, `clear-status`, `list-status`, `set-progress`,
`clear-progress`, `log`, `clear-log`, `list-log`, and `sidebar-state`.
Observed live on this machine, every one scoped by `--tab=<surface-id>`:

```
set_status     maestro 'Fleet alpha - Maestro attached' --color '#22c55e' --tab=D151CC7D-...
log            --level=info --source=copilot --tab=BB08272F-... -- "dylan: prompt - spawn a fleet..."
set_progress   0.18 --label="dylan: spawn a fleet of agents..." --tab=BB08272F-...
clear_progress --tab=081783A3-...
```

Consequences:

- **The c-0026 single-line `¦` wire format is retired.** It exists only to
  squeeze a tree into a per-workspace free-text field. Per-terminal channels
  were available from the start.
- **c-0027's status design is native.** `set-status` carries a colour, per tab.
- **The task list has a channel.** `log` is append-only per tab with `--level`
  and `--source` - exactly the growing, session-attached list the user
  described.
- The fork's own README already named all three: *"status bar, sidebar log
  entries, and desktop notifications."* No cycle read it.

## F2 - cmux has first-class Copilot support

`copilot` is one of sixteen supported agents: binary `copilot`, installed file
`~/.copilot/config.json`, session restore `copilot --resume <id>`, Feed bridge
`PreToolUse`. Its session store records the agent session id, cmux workspace id,
**surface id**, cwd, pid, a sanitized launch command, and a lifecycle of
`running`, `idle`, `needsInput`, `unknown`.

That is a native answer to three carried items at once: c-0025's ambiguous
session resolution, c-0027's state taxonomy, and - as a consequence rather than
a feature - **session restore**, materially the durable-lifecycle capability
c-0025 retired as the largest remaining build item.

**Not installed on this machine**, so none of it is measured.

## F3 - Dock is a second, resizable, persisted surface

The right sidebar is a full pane container on the same surface and split system
as the main area, with divider positions preserved across quit and update,
scriptable via `--placement dock`. A Dock terminal runs an arbitrary command, so
a TUI there escapes the sidebar interpreter entirely - no `@State` ceiling, no
silently-skipped syntax, no SF-Symbols-only constraint. Recorded as a candidate
for n-0013's resizable-panel question rather than adopted.

## Decisions

**1. Native-first, as a standing principle.** *User: "we should be leveraging as
much native cmux as possible, and only provide extensions where core
functionality falls apart or can't bridge a gap. I would like to leverage cmux's
inbuilt copilot integration so that we can reliably delegate that integration to
someone else and inherit it from the platform itself."*

This is recorded as **n-0016** because it decides future questions without
another round trip. The value named is not only the feature but the **ownership**
- someone else maintains the integration.

**After this, the subagent tree is the only capability Maestro adds.**

**2. The c-0027 lane push is retired, one cycle after it was decided.** Not
because the reasoning was wrong - most-urgent-wins aggregation was a sound fix
for the granularity problem - but because it was reasoning about the wrong
channel. A per-tab status pill is the correct granularity, renders in the stock
sidebar, and does not compete with the lifecycle cmux infers natively.

**3. The hook install is treated as measured work, not a silent step.** The loop
flagged, and the user accepted, that `cmux hooks setup copilot` writes
`~/.copilot/config.json` - the file whose hook entries broke every session in
this environment three times in one day. Backup, install, verify a session
survives a tool call, keep a one-command rollback.

## Limitations

- **Nothing was measured this cycle.** Every finding is from published
  documentation, the CLI contract, or passive observation of an event log this
  machine had already written. No cmux command was run against a live session.
- The three per-tab channels are documented and observed **being emitted**;
  they have not been observed *rendering* in either sidebar.
- cmux's Copilot integration is not installed here, so its lifecycle values,
  its session store, and its restore behaviour are all unobserved.
- Two grounded questions asked of a budget of six.
