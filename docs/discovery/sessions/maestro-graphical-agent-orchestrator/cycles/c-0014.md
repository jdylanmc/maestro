# Cycle c-0014 - A question about firstmate reversed yesterday's decision

## How it started

The user asked how firstmate handles permissions.

Firstmate's answer is that it does not. Permissions are pre-negotiated at spawn
through the brief's "mode and yolo contract"; the control plane is three verbs -
`interrupt`, `exit`, `relaunch`, with teardown permanently excluded; and human
involvement arrives through the wake queue's actionable/absorbable split rather
than through approval prompts.

But answering it meant reading the neighbouring reference, and
`orbit-arch.md` describes an Electron application that receives permission
requests from the **Copilot SDK**, auto-approves read-only operations, renders
permission cards, and times unanswered requests out into denials.

c-0013 had settled the integration seam one cycle earlier - after probing two of
three seams. The third was the one that answers the question.

## Reinterpretation weakened a decision made one cycle ago

`n-0008` took a `weakened` verdict, maturity `researched` -> `vague`. The ACP
measurements are untouched and still cited; what failed is the **inference**
built on an incomplete survey.

The weakening reopened three priority-debt rows. That is the mechanism that
forced the seam to be re-examined rather than quietly inherited, and it is the
strongest argument yet for the invariant being real machinery rather than
bookkeeping.

## What the SDK probe found

`@github/copilot` on npm is a loader. The SDK ships **inside the platform
package** at `copilot-sdk/`, with full typings.

- `SessionConfig.onPermissionRequest` - an answerable callback.
- Omit it and requests are "surfaced as events and left pending for the consumer
  to resolve via the pending permission RPC" - a pull model as well as a push
  one.
- `permissions.pendingRequests()` is documented as returning "the set of
  `permission.requested` events that have not yet been followed by a matching
  `permission.completed` event."

That last line is the Attention predicate. c-0010 derived it, c-0012 measured
it, c-0013 concluded it was unavailable - and it was the runtime's own published
contract the whole time, with a first-class RPC that returns it. Maestro never
needs to reconstruct Attention from the event log.

The decision union is rich - approve-once, for-session, for-location,
permanently, reject, user-not-available, and four distinct denial causes - and
the user's stated habit of running with broad permissions is `setApproveAll`, a
toggle rather than an architecture.

## Where it stopped

`start()` and `createSession()` succeeded, returning session `4dec7e07-...`.
`sendAndWait` failed: **"You have exceeded your monthly quota."** Only `auto`
was available, so there was no cheaper fallback.

**The callback was never observed firing.** The user accepted settling the seam
on documentary evidence with a re-test trigger on quota reset, which is recorded
as an explicit accepted unknown carrying the risk that this is the same evidence
class that produced the c-0006 spawn requirement measurement later falsified.

## The lesson worth keeping

c-0013 was not careless. Its measurements were sound and are still cited. It
treated a seam **survey** as complete when it had covered the two seams the loop
happened to know about. Nothing in the cycle protocol catches that - only the
reinterpretation step did, and only because a user asked about something else
entirely.

## Limitations

- Permission behaviour is established from shipped declarations and a second
  application's implementation, not from observation.
- The bundled SDK reports `@github/copilot-sdk@1.0.9-preview.2` inside a CLI of
  a different version, so the surface may move.
- No rename check, and no subagent spawned, so the SDK's typed-event path for
  `subagent.started` is unconfirmed.
