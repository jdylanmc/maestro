## Evidence

**The `Attention` handoff completed, three cycles late.** `/domain-mapping` ran
in a live user turn and confirmed the term into `CONTEXT.md`, resolving a
four-source disagreement as **separate concepts**: the per-Fleet condition is
the domain term, and the cross-Fleet ranking that consumes it is presentation.
The ranking reading was falsified by c-0010's confirmed total-Fleet-isolation
decision. The user chose the broad reading, so Attention means the Fleet *wants
its human*. `docs/adr/0002` was approved separately.

**The confirmed trigger set maps onto four SDK surfaces**, verified against
`@github/copilot-sdk@1.0.11-preview.2`: unmatched `permission.requested`;
`session.error`; `session.idle` with `aborted: true`; and `session.idle` with
`aborted` falsy or `hooks.onSessionEnd`.

**The permission surface is version-volatile.** `0.3.0` and the copy bundled in
`@github/copilot@1.0.40` make `onPermissionRequest` required and expose no
`pendingRequests()`. Version ordering was checked *before* concluding anything -
`npm view` runs `0.x` through `1.0.11-preview.2` - so 0.3.0 predates c-0014's
reading and the pull model was **added**, not removed. **c-0014 is confirmed,
not falsified.** But the current doc says `pendingRequests()` "**Reconstructs**
... from the session's event history", so c-0014's "a query rather than a
reconstruction" is narrowed: it *is* a reconstruction; the runtime performs it.

**Research established the two ends of the Presentation Check.** Playwright's
`_electron` attaches over the Chrome DevTools Protocol and asserts multi-panel
state idiomatically; native menus and dialogs are invisible and must be stubbed.
A WezTerm route can automate roughly **40-50%** of on-screen verification and has
**no macOS accessibility tree at all** (issue #913), which closes XCTest,
Appium, and AppleScript together and leaves only screenshot plus optical
character recognition.

**Prototype n-0009-c-0016 - the cycle's main result and its sharpest lesson.**
Acceptance-slice **step 4 is machine-verifiable**: one click, then four
auto-retrying assertions, passing 3/3 unpackaged and 3/3 against a packaged
`.app`. Step 4 was the only slice step with no external ground truth, so it was
the step that decided whether the Presentation Check was viable at all. The
**negative control passed** - an immediate non-retrying read still saw stale
state - which is what makes the positive result evidence rather than decoration.

**And the probe's other conclusion was wrong.** It reported that disabling
`enableNodeCliInspectArguments` blocks Playwright, isolated by a control
variant. The user reported repeated "probe quit unexpectedly" dialogs, and the
crash reports gave the real cause: `SIGKILL (Code Signature Invalid)`,
`CODESIGNING / Invalid Page`. `@electron/fuses` rewrites the Mach-O *after*
electron-builder signs it, so macOS refused to execute the binary at all;
`Process failed to launch!` was downstream of the OS kill. The fuse claim
reverts to documentary only. Newly established instead: **flipping Electron
fuses without re-signing produces a binary macOS kills on sight.**

The failing tests looked exactly like the researched failure mode, which is why
the wrong conclusion was convincing, and nothing inside the loop caught it. It
was caught only because the user mentioned an operating-system dialog the loop
never thought to look for. Recorded as a rule: **a prototype asserting a
negative result must establish *why* the negative happened, not merely that it
happened.**
