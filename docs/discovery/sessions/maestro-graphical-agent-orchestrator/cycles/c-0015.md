# Cycle c-0015 - The harness splits in two, and the debt table finally empties

## The question had to be asked twice

The first attempt was rejected outright: *"I'm not sure I even follow what you
are asking."* It had been framed in this loop's own vocabulary - state truth
versus presentation truth, route-agnostic assertion - which is precise and
useless to the person answering.

Restated in plain terms, it was answered immediately, and then improved on.
Recorded because it is a repeatable failure mode: reaching for internal
vocabulary in a user-facing question spends the user's attention on translation
instead of on the decision.

## The split that survived

The six acceptance-slice steps sort by whether anything outside the application
can establish them. Three are fully external. Three carry a presentation half.
**Step 4 - selecting a Fleet re-scopes every panel - has no external truth at
all.**

That asymmetry is the design:

- **State Oracle** - asserts steps 1 through 6 from `git worktree list`,
  `git branch`, `ps` by recorded process group, `events.jsonl`, and the SDK's
  `listSessions()`, `resumeSession()`, and `permissions.pendingRequests()`. It
  needs **no cooperation from the route under test**, so a route cannot assert
  its own success and no stack is advantaged by being easy to instrument. It is
  buildable before any route exists, which is what unblocks `n-0003`.
- **Presentation Check** - what only appears on screen, automated as far as each
  stack allows, starting with Playwright against Electron.

## What the user changed

The loop asked who checks the visual steps. The user answered a better question:
**user-interface automation belongs in the stack selection**, because automated
regression checks are the work that follows the MVP. Storybook and Playwright
named as reference points.

Then two constraints that sharpened it further: *"i can't afford human testers,
so we will test with machines as much as we can"* and *"but first - we have to
prove an MVP on a stack."*

Together they settle more than the question asked:

| Consequence | |
| --- | --- |
| Manual steps | A stopgap of last resort. Whatever survives is a **cost recorded against that route**, not a neutral choice |
| The rubric criterion | **Measured, not assessed** - how far a route automates its own Presentation Check *is* the evidence |
| Pass/fail | Never depends on automation reach. A route checked by hand still passes if it behaves correctly |
| Scope | Harness sized for Electron only. Breadth before a proven MVP would repeat the c-0013 mistake |

## The criterion is not neutral, and that is on the record

A component-driven web stack reaches Storybook and Playwright directly; Tauri
reaches Playwright through WebDriver; Swift uses XCUITest; a terminal surface
exposes almost nothing to any of them.

Naming this criterion therefore predicts part of the ranking before a line is
written. That is a legitimate decision by the person who owns it - and it is
recorded as a decision so that when the WezTerm route scores badly, the reason
is visible as a choice made here rather than as a discovery made at the end.
