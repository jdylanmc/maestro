# Cycle c-0012 - Two prototypes, and both of the comfortable assumptions broke

## What this cycle was for

Eleven cycles of reasoning had produced a route plan whose two hardest claims
had never been tested against anything real. This cycle tested them, under two
approved prototypes, and both came back with a correction attached.

Selection was deterministic and, for the first time, discriminating: with eight
nodes on the tree, rule 3 fired on shared blockers and chose `n-0003` - the v2
Electron MVP - over `n-0001` on the lower-maturity tie-break.

## Finding 1 - packaging holds, and it explains c-0006 better than c-0006 did

A packaged, unsigned `.app` launched through LaunchServices reproduced c-0009's
development-run results exactly: **0 survivors** on graceful quit, **9** on a
Force-Quit simulation with no reaper, **0** after reap-on-launch.

The interesting part was incidental. The packaged application's own parent
process identifier is **1** - it is a child of `launchd`, the identical shape
that made v1.0's detached `herdr server` dangerous. And it is harmless, because
the application is its own process-group leader and each Fleet gets its own
group.

So the c-0006 lesson was stated one notch too wide. Reparenting was never the
defect. **Unowned** reparenting was. Maestro is itself a reparented process and
that is fine.

## Finding 2 - the Attention predicate fires, and it is narrower than we thought

c-0010 derived Attention as an unmatched `permission.requested` and admitted it
had never seen one, because no unresolved request exists in any of the 674 local
session databases. This cycle constructed one.

On a genuinely blocked live Session, request `dd7f6347` was raised and left
unanswered, and it was still unmatched when sampled twice, 25 seconds apart. A
separate Session showed the full cycle: requested, then completed 1.1 seconds
later with `{"kind": "approved"}` when a human pressed a key.

Three implementation facts came out of it: the join key is **`data.requestId`**,
not `toolCallId`; `result.kind` discriminates approval from policy denial; and
the events are in **`events.jsonl`**, not in `session.db`, which holds only
`inbox_entries`, `todos`, and `todo_deps`.

Then the constraint. Without `--allow-all-tools`, a **non-interactive** Session
completes every permission request instantly as
`denied-no-approval-rule-and-could-not-request-from-user`. Nothing is ever
unmatched. **A Fleet driven with `-p` can never surface Attention**, so
acceptance-slice step 5 is unreachable through it. The integration mode stopped
being an implementation detail and became a requirement-level constraint - and a
new blocking node, `n-0008`, pointing first at `copilot --acp`.

## Finding 3 - a live Session does not tear down like a synthetic one

The blocked Session held **eight processes in one process group**: `copilot`,
two `npm exec` wrappers, Model Context Protocol servers, and `OsgWikiMcp` - the
same binary that raised the orphan prompt in c-0006.

| t after `SIGTERM` to the group | Survivors |
| --- | --- |
| before | 8 |
| +0.5 s | 6 |
| +1.0 s | 6 |
| +1.5 s .. +3.0 s | **5, stalled** |
| after `SIGKILL` escalation | **0** |

c-0009's synthetic `sh`/`sleep` trees reached zero on `SIGTERM` alone. The real
runtime does not. **The synthetic result overstated graceful teardown.**
Escalation is not a safety net; it is the step that does the work. c-0006 had
already observed wrapper processes ignoring `SIGTERM` - this is the same
behavior, now measured against the real thing rather than inferred.

A quieter finding: `copilot` **self-assigns its own process group** even when
spawned with no detach flag, and its Model Context Protocol servers inherit it.
A supervisor gets a clean per-Session boundary for free - but must still record
the group, because a group it does not record is a group it cannot reap.

user was absent.

That divergence is now two cycles old and still needs `/discovery`.

## The priority-debt table is no longer empty

Two P0 nodes entered at maturity `vague` and block three P1 routes that had
already advanced, so six debt rows opened. This is the invariant working: no
route below Electron gains depth until the integration mode and the harness
reach maturity `researched`. `n-0008` ranks first, so rule 2 - not rule 3 -
selects next cycle.

## A bookkeeping defect, found and corrected

Every `state-digest` up to c-0011 was the per-file digest of `discovery.md`
alone, not the five-line manifest the schema specifies. `domain-model.md`,
`requirements.md`, and `evidence.md` were never inputs, so drift in any of them
would have gone undetected. Nothing had actually drifted - the entry comparison
reproduced bit for bit under the old convention - but eleven cycles of
verification were narrower than they claimed. c-0012 records the conformant
manifest digest. **c-0013 must not read that change as drift.**

- The verification-seam decision is the only one this cycle not taken in a live
  user turn.
